## Delivered behavior

The real desktop knowledge center now provides a local, single-Group import → encrypted storage → BM25 evidence search → exact stored citation/text inspection → confirmed source unlink/delete workflow. It can be reached through **先使用本地资料** on first launch without a model Key. That choice dismisses the current launch's onboarding and opens Knowledge; it does not seal a model, mark it applied, set an applied fingerprint, claim agent readiness, or test a provider.

`KnoweServer._health_conn` invokes production `LocalKnowledgeService` dispatch for `/api/knowledge/local/{sources,import,search,detail,delete}` after the existing Runtime Secret authentication and shared HTTP controls. There is no additional listener, group registry, grant mechanism, provider call, automatic model answer, embedding request, or OCR request.

Imports carry the user-selected filename and base64 bytes, never a renderer filesystem path. Seven native types are supported through in-memory parsing: TXT, Markdown, HTML, DOCX, PPTX, XLSX, PDF (plus existing filename aliases). The file cap is 20 MiB; the import HTTP envelope alone permits 28 MiB. OOXML import permits at most 4096 members, 64 MiB total expanded size and 16 MiB per member, and rejects encrypted ZIP entries. PDF byte imports cap pages at 1000 and serialize PDFium parsing across concurrent import worker threads. Filename/path traversal, unsupported extension and invalid byte envelopes fail before publication. Parser exception details are neither returned nor logged because they may contain document text.

`rag_sources` extends the existing encrypted store with authenticated ciphertext for the original bytes and source metadata, including filename and optional course attribution. Source IDs are generated by the backend as random `src_<uuid>` values. Existing chunk encryption, keyed fingerprints and master-key verifier are reused. Wrong-key opening refuses reads/writes and closes the failed connection; it never replaces the verifier, key or existing content. Windows production routes use the existing DPAPI-protected key boundary.

All reads and writes consult authoritative `GroupRepository` state. Unknown/deleted Groups, pending deletion and unbound course scopes are denied. Archived Groups can list/search/inspect but cannot import/delete. An ID alone does not authorize reading a source; the addressed Group must already have the canonical source link. A course query must match both an authoritative course binding and the encrypted source attribution. Imports recheck Group lifecycle and course binding identity after worker parsing and before synchronous publication; search rechecks current Group/course and source authorization after worker scoring.

Source deletion removes only the addressed Group link. Canonical reference counts retain a shared source for remaining Groups. Removing the last reference removes original, metadata, chunks and unreferenced embedding rows, clears the in-memory indexes, and truncates the WAL after secure deletion. Real `/groups/delete` and `/groups/source-unlink` routes also perform this cleanup; they reopen/verify an existing local store before destructive authority changes after restart. Reopening reconciles unlinked documents, including an import interrupted between chunk persistence and canonical linking. Vector hashes still referenced by another stored document are retained.

BM25 runs locally without a Key or network, rebuilding its scoped corpus from ciphertext on first search after restart. The cache holds at most four scopes, each admitted only below two million evidence-text characters; oversized corpora remain searchable without being retained in that cache. Source/group mutations invalidate cache entries. The UI labels the mode as lexical and explicitly says semantic search/OCR are not enabled and results are evidence rather than verified answers. Scan-only PDF sources show `needs_vision` and zero searchable text chunks; mixed PDFs identify their unparsed image pages rather than claiming completeness.

The renderer includes file import/busy/error states, source list, query/results, stored location and text inspection, and explicit deletion confirmation using the existing visual tokens. A panel mount is keyed by Group + course and owns its own request epoch; it also checks the existing renderer Group deletion generation before committing responses. A→B→A, deleted Group, delayed search/detail, and unbound-course responses cannot repopulate old visible data.

## Existing knowledge panel compatibility

Rendered QA exposed an old mismatch: the initial “all Groups” UI sent multiple `group_id` values although canonical knowledge HTTP requires exactly one. KnowledgeScopedView now requires selection before mounting either local or existing knowledge panels. This respects the existing backend boundary.

For the whole selected Group, the old panel now omits an explicit `source_id` filter. Authorized sources continue to be derived by the unchanged backend from GroupRepository. Treating every linked local source as an explicit narrow filter had incorrectly excluded approved-global and course-only old knowledge objects after import. Course selection remains narrow: unproven/ownerless objects are still denied. There are no Task4 contract/repository changes or backend permission expansions.

## Explicit limits and next acceptance boundary

- This slice retrieves and inspects evidence only. It does not generate answers, enable cloud embeddings/OCR, render original PDF highlights, or resolve the pending local-vs-cloud/provider choice.
- The existing Windows DPAPI master-key design is reused, not a new cross-platform key strategy or rotation/migration implementation. Unavailable/wrong key remains an explicit storage failure.
- Release packaging, the known dependency exclusion involving NumPy/RAG imports, installer/packaged Electron smoke checks and broader Task4/Task5 work remain separate. No release spec/dependency rewrite was included.
- Whole-repository backend failures are not repaired or waived by these tests. An independent implementation review follows this scoped commit. This report establishes a usable/testable local vertical slice, not whole-product commercial acceptance.

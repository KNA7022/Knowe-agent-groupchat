Important pinned-SDK facts:

- `Memory.__init__` in `mem0/memory/main.py:488` invokes all three factories, opens `SQLiteManager`, and optionally constructs a reranker. A default `MemoryConfig()` is evaluated during module definition. Always pass an explicit internal config; never call the default constructor or `Memory.from_config`.
- `VectorStoreConfig.validate_and_create_config` has a closed map plus dynamic imports. `LlmConfig.validate_config` and `EmbedderConfig.validate_config` also reject unknown providers. Registering only factories is insufficient.
- `LlmFactory.register_provider` exists. Embedder/vector factories expose provider-to-class dictionaries but no public registration method; using these maps is a deliberately pinned internal compatibility dependency.
- `EmbedderFactory.create` always constructs `BaseEmbedderConfig(**config)`. Its accepted `model_kwargs` field can carry an opaque internal operation handle; arbitrary new top-level keys cannot.
- The actual `Memory.add(infer=True)` implementation is an additive pipeline: retrieve 10 existing memories, one extraction LLM call, batch embeddings, MD5 duplicate elimination against retrieved records and within the new batch, insert and entity linking. Its old-looking docstring mentions update/delete, but the observed implementation does not autonomously reconcile contradictory facts. Do not advertise stronger semantic duplicate or correction guarantees.
- `Memory.search` uses actual SDK embedding, semantic scoring and optional entity boosts. Internal entity searches strip filters to session identifiers, and run searches in a `ThreadPoolExecutor(max_workers=4)`. Namespace isolation must survive removal of custom metadata filters and lack of ContextVar propagation.
- Lazy `entity_store` clones the vector config and changes `collection_name`. `Memory.close()` closes history only; the application must also release vector/entity collections and operation bindings.
- `mem0/memory/setup.py` creates `MEM0_DIR` and can write a random config UUID. Telemetry and notices have remote paths. In addition, `mem0/utils/spacy_models.py` downloads `en_core_web_sm` if spaCy is installed without its model. Telemetry disablement alone is not a no-network guarantee.

## Smallest validated SDK extension

Add private application modules under `backend/knowe_memory/` (names proposed): `mem0_bootstrap.py`, `mem0_config.py`, `mem0_adapters.py`, `service.py`. Do not edit installed SDK files, inject fake `mem0.*` modules, overwrite a built-in provider registration, use `model_construct`, mutate a validated default into a custom provider, or duplicate the SDK constructor/algorithms.

Use a unique provider name such as `studycrew_ephemeral_v1` for vector storage and `studycrew_governed_v1` for each model factory. Registration runs once under a bootstrap lock, before constructing any instance. An absent map entry can be added; an identical entry is idempotent; any collision or changed pinned signature fails closed. Maps never change during active work.

Implement the following normal Pydantic subclasses, with `extra='forbid'`, required fields and ordinary validation:

1. `StudyCrewVectorConfig(VectorStoreConfig)` narrows provider to the one literal, overrides the inherited validator **by the same method name** `validate_and_create_config`, and validates the nested `EphemeralVectorConfig`. That nested model includes collection name, dimensions, metric, model identity and opaque operation/projection binding; it has no path/host/URL/key/client fields. Override the `config` annotation to the internal typed model or typed input union so the inherited `Optional[Dict]` cannot erase the model. Validate again at factory entry.
2. `StudyCrewLlmConfig(LlmConfig)` and `StudyCrewEmbedderConfig(EmbedderConfig)` similarly narrow provider and override `validate_config` by the same name/decorator. Accept only the exact internal field set; reject base URLs, API keys, vision, arbitrary model kwargs and unknown provider options.
3. `StudyCrewMemoryConfig(MemoryConfig)` declares those three required narrowed fields with no inherited default factory, `history_db_path=Literal[':memory:']`, `reranker=None`, pinned version and fixed bounded custom instructions. Validate the whole object normally. Construct `Memory(config=validated_config)` directly.
4. Register the LLM with `LlmFactory.register_provider(name, class_path, InternalLlmOptions)`. Its validated config class need only satisfy the pinned factory/base interface; use an internal Pydantic options model rather than the default config that creates an unused HTTP client. The adapter implements `LLMBase.generate_response` and returns the validated SDK-compatible JSON string.
5. Register the embedding class in the embedder map. The validated outer config passes only supported `BaseEmbedderConfig` fields: real model identity, dimensions, and `model_kwargs={'studycrew_operation_handle': opaque_handle}`. No authority/secret is serialized here. The adapter validates the resulting base config and resolves the handle from the private registry. The base config creates an unused httpx client; explicitly close it in the adapter lifecycle and prove it never sends. A later optimization must not silently rewrite the factory.
6. Register the vector class in the vector map. It implements `VectorStoreBase` against an in-process collection registry. Config `model_dump()` and deep-copy/reconstruction must preserve the opaque binding. The nested config allows validated assignment of `collection_name`, since the SDK performs it for entities; all authority and scope live in the immutable registry entry, not writable config fields. Only the exact main name and SDK-derived entity name for that entry are legal. Reject `mem0migrations` and any unrelated name.

Pydantic same-name validator overriding and nested-subclass preservation are a **first implementation gate**, not a runtime result established by this design. Test both direct typed construction and dict validation, repeated validation and entity cloning against the locked Pydantic version. If they do not behave as required, stop adapter integration and document the concrete incompatibility; do not fall back to validation bypass/Qdrant or a copied constructor. This scoped compatibility layer retains the real `Memory` implementation.

## Bootstrap, storage and lifecycle

Before any transitive Mem0 import, backend startup sets `MEM0_TELEMETRY=False`, sample rate zero as defense in depth, and `MEM0_DIR` to a dedicated private per-process temporary directory. Do not rely on a late environment change, and do not restore these process-wide variables while SDK modules remain loaded. If Mem0 was imported before controlled bootstrap, disable this feature and require a clean backend restart. Inspect distribution version without importing its package, enforce the pinned version, then import/register/construct explicitly.

The import chain is concrete: even `from mem0.configs...` first executes `mem0/__init__.py`, which imports `mem0.client.main` (including `requests`, setup and telemetry; module-level `setup_config()` at line 37) and then `mem0.memory.main` (setup at line 454 and default `MemoryConfig()` at line 488). `mem0.memory.setup` itself calls `os.makedirs` while importing. Telemetry imports PostHog; notices import urllib and contain a GitHub config fetch. Later add/search calls invoke lemmatization/entity extraction, which import `spacy_models`; only when spaCy is importable and `en_core_web_sm` is absent does `_ensure_model_available()` invoke `spacy.cli.download`. Safe bootstrap must precede this entire package chain, not just `Memory()`.

Minimum internal configuration is the three unique validated provider selections above, a positive fixed model dimension, opaque operation-bound collection name, `history_db_path=':memory:'`, `reranker=None`, `version='v1.1'`, no vision, no SDK procedural memory type, and no provider endpoint/key/path. The LLM receives only an operation handle, chosen model and capped generation parameters; embedding receives model/dimensions and its one allowed handle field. All omitted provider configuration is an error, not permission to inherit Mem0's OpenAI/Qdrant defaults. Import/config/optional-NLP failure marks only `semantic_memory` unavailable before content reaches the SDK; the rest of StudyCrew and other offline features remain available. UI readiness must distinguish this component failure from application startup failure.

The directory can contain only SDK-generated non-content UUID/config metadata. No conversation, prompt, vector, entity, key, authority binding or source path is written there. History is literally `:memory:`; assert the SQLite database-list path is empty and set in-memory temp storage before the first operation. Bound history to an operation lifetime. Do not enable graph/reranker/vision/procedural paths. `memory_type='semantic'`/`'episodic'` is not supported by this SDK parameter: keep those types in StudyCrew metadata and leave SDK `memory_type` unset.

Use an isolated packaged Python environment with base Mem0 dependencies only. Do not include `mem0ai[nlp]`, spaCy, model packs or graph/vector extras. Bootstrap verifies the environment cannot enter the automatic spaCy model-download branch. An ambient development environment containing spaCy with a missing model fails feature readiness; no attempt to repair/download it automatically. Future entity NLP requires separately governed prepackaged local assets and no-download tests. The no-spaCy fallback is an actual SDK path (empty entity extraction/original-text lemmatization), not a replacement extraction engine. Nevertheless exercise lazy entity creation and storage in compatibility tests, so later NLP availability cannot create a plaintext persistence hole.

Read-only packaging inspection found `backend/StudyCrewBackend.spec:105` lists only browser/yaml hidden imports, `runtime_hooks=[]`, and line 117 excludes NumPy/scipy/MKL but **does not exclude spaCy**. `scripts/backend-build.mjs` selects an available Python 3.12 interpreter, inherits its environment, and fingerprints a short dependency list that currently omits Mem0/Pydantic and optional NLP. Installing base Mem0 without extras therefore does not establish that a frozen app lacks ambient spaCy: PyInstaller can statically collect optional imports from the build interpreter. Future packaging work must use a locked build environment, explicitly exclude spaCy/NLP model modules in the base memory profile, examine Analysis/PYZ contents and optional import closure, include the lock/SDK/config dependency versions in the build fingerprint, and add early bootstrap/runtime-hook coverage. Reconcile the existing NumPy exclusion with both the current exact index and intended USearch dependency; do not silently ship a vector backend that cannot import. Validate the resulting executable under network denial, not merely the source environment/spec. No spec/build script was changed or build executed in this task.

Suppress content-bearing SDK logging before import using a fixed prefix-dropping filter on the configured output handlers (logger ancestor filters alone do not filter propagated child records), plus disabled propagation/null handling for SDK-owned loggers. Apply equivalent filtering to any later-created handlers. Do not merely raise log level: SDK warnings/info interpolate entity text and memory data. StudyCrew emits only allowlisted event codes, opaque operation IDs and counts. Never format raw SDK exceptions, Pydantic input errors, HTTP bodies or tracebacks into user/audit logs. Test stdout/stderr, structured audit and child loggers. Resetting telemetry is not a substitute for this.

Explicit teardown closes history, unused base HTTP client, operation gateway clients on their owning event loop, all main/entity collections, transient mapping and source buffers; it revokes the registry handle. Python cannot promise physical RAM erasure or control OS paging/crash dumps. The enforceable guarantee is no application-written plaintext content and prompt release of references; desktop deployment should keep content out of crash diagnostics. Startup residual scan uses the known application temp root and manifest of owned directories, never broad home/temp deletion. Unexpected content or persistent SDK DB/vector files make readiness fail; clean only validated application-owned artifacts under the established deletion workflow.

## Interfaces, authority and concurrency

Proposed narrow application contracts (typed/frozen records, not public arbitrary dictionaries):

```text
MemorySelection(user_id, group_id, course_id, allowed_sensitivity, memory_kind)
EvidenceRef(source_id, source_version, chunk_or_message_id, range, content_digest)
MemoryOperation(op_id, canonical_task_authority, selection, source_versions,
                scope_generation, provider_binding, embedding_identity, limits)
EmbeddingIdentity(model_id, revision, dimensions, normalization, execution_location)
GovernedEmbedding.embed(texts, *, operation, purpose) -> validated vectors
MemoryService.extract(operation, evidence) -> candidate summary
MemoryService.remember_direct(operation, user_statement) -> repository outcome
MemoryService.recall(operation, query, limit) -> authoritative records + scores
MemoryService.approve/revise/reject/delete(selection, memory_id, expected_version, ...)
```

The service resolves authenticated local profile/user ownership, current group membership, course and source access **before** issuing `MemoryOperation`. A group alone does not establish user ownership. The canonical task resolver re-reads a real backend-owned task/run; bind the operation to its purpose, group/course/source scope and configured budgets. If no relevant running task exists, the application workflow must create a specific user-triggered memory task with those bounds through Task Runtime, or decline/defer extraction. Do not create a generic helper/settings-probe run to gain model authority. A renderer-supplied `LegacyToolAuthority`, dictionary or naked API key never enters this API.

Each operation gets fresh SDK/model adapter instances and a private random registry handle. Adapter instances keep an immutable operation binding; mutable cancellation/counters are separate, lock-protected state. No shared mutable `current_authority`, no environment credential injection, and no trust that ContextVars cross SDK thread pools. Gateway construction uses `authority_provider=lambda: captured_canonical_authority`, and gateway revalidates the live run on every call. A frozen provider binding supplies `credential_provider=lambda: resolve_provider_credential(binding)` at the request boundary, with `api_key=''`, retries zero. Resolve/validate lease purpose on each call; settings changes cannot retarget an in-flight operation. Registry and adapter handles are private capabilities, not user-visible configuration.

Use synchronous `Memory` in a bounded worker executor, leaving the backend asyncio loop free. `generate_response/embed/embed_batch` schedule governed async calls onto that captured loop with `asyncio.run_coroutine_threadsafe` and wait only from a worker thread, never the loop thread. Each operation's gateway calls are serialized: the current transport's `last_attempts` accounting is mutable and must not be shared by simultaneous calls. Avoid lock inversion: do not hold repository/index locks while waiting for model I/O, and do not have loop callbacks wait for the SDK worker. Entity parallel searches access only locked in-memory adapters with the captured immutable binding.

On cancellation/deadline, set a sticky cancellation flag first, revoke the operation's commit capability, cancel outstanding gateway futures, and let gateway record its cancelled terminal effect. SDK catches some embedding/vector exceptions and tries fallback loops; every adapter method checks the sticky failed/cancelled flag so those loops cannot restart egress or write. Join/drain the worker within the finite transport/operation deadline before final disposal; `asyncio` task cancellation alone does not stop its thread. If a worker fails to terminate, quarantine its private arena/handle, refuse all commits/results, and mark readiness unhealthy. Do not kill the backend or silently reuse the instance.

## Local embedding and bounded extraction

The user's local OCR/local embedding default is authoritative. `knowe_rag/retrieval.py` contains a cloud-embedding assumption, but it does not authorize cloud upload. This task consumes a governed local embedding interface; it does not choose/download model packs or implement toy embeddings. Model absent/unready means explicit semantic-memory unavailable (existing separately labeled lexical retrieval may still operate); never automatic cloud fallback. Optional cloud embedding/extraction requires the selected registry capability, real operation authority, exact egress approval where applicable, and credential lease. Index identity includes model/revision/dimensions/normalization/location; a change invalidates/rebuilds the projection, never mixes embeddings.

Suggested first-release ceilings, validated as configuration and narrowed by Task Runtime's remaining budget: 16 KiB/8 messages input per extraction; 8 extracted facts of at most 1,024 UTF-8 bytes each; 2,048 output tokens; exactly one chat generation attempt; at most 3 embedding batch calls (query, extracted facts, entities), at most 32 embedding texts/16 KiB total per operation; 30 seconds wall clock; at most two active operations. Pre-count the complete SDK-generated prompt, including existing memories/history, before egress; oversize requests fail before spending. These are release defaults for testing/tuning, not hidden promises that arbitrary models fit.

Implement a real batch embedding method; default per-text base loops would consume unnecessary calls. Reserve/check both operation and Task Runtime budgets before each cloud call. Provider retries and ad-hoc repair/fallback LLM calls are disabled. A failed batch marks the operation terminal before Mem0's individual fallback loop can run. Search has zero LLM calls and a bounded query/entity embedding allowance (SDK considers at most 8 query entities). Rebuild embedding cost is a distinct bounded local job; no silent cloud rebuild at restart. Page/shard large approved scopes with explicit size ceilings or readiness/backpressure rather than unbounded decrypt/embed work.

Validate model response at the LLM adapter boundary before returning JSON to Mem0. Require a JSON object containing only `memory`, a bounded list of SDK-compatible records (`id`, `text`, `attributed_to`, optionally `linked_memory_ids`); enforce strings, lengths, count, unique sequential IDs and allowlisted attribution. Linked references must belong to the captured existing-results set and cannot confer ownership. Reject code fences, extra JSON, unknown fields, tool calls and any update/delete/status/scope/approval fields. Do not use SDK's permissive JSON recovery as the application security boundary. Input is untrusted quoted evidence; fixed extraction instructions must never promote document instructions into authority. Schema validation bounds execution, but cannot prove factual truth: every inferred output remains a candidate and shows its source evidence to the user.

The memory service runs deterministic sensitivity/secrets checks on raw evidence, generated facts and final outbound content. Sensitive classification from source and policy cannot be downgraded by generated text. A fact's memory approval is not approval to send it to a provider. Current gateway DLP is pattern-based; it does not cover every grade, weakness or personal inference. Until exact-payload approval integration exists for semantic sensitivity, **deny cloud egress of any non-public/inferred-sensitive evidence or retrieved context even when regex DLP finds nothing**. Local computation or deferred candidate creation is allowed. If cloud sensitivity approval is later supported, each fully constructed request requires its own fresh payload-bound approval/grant; extraction approval cannot authorize a subsequent embedding request. Secrets are rejected as memory content rather than awaiting ordinary approval.

## Namespace and projection rules

Partition every arena by `(opaque_user, group, course, kind, sensitivity, status_namespace, model_identity, generation)`. Encode names as opaque random tokens or keyed digests; never place user names/course titles/source paths into collections. Candidate and Approved are distinct arenas. Tombstone data is kept only in repository suppression checks, never embedded or made searchable. A normal recall selects only Approved arenas after authorization and before constructing the SDK. The SDK's `user_id` is an opaque subject identifier; group/course are not entrusted to its session filters.

Each vector adapter is bound to one exact partition. Every entry point, including `list`, `get`, `search_batch`, collection enumeration and lazy entity lookups, enforces it even with missing/forged filters. Only required equality filters are supported initially; unknown operators, OR/NOT/wildcards or attempts to broaden scope are rejected. Collection creation receives no arbitrary filesystem/network location. Return bounded objects with `id`, `score`, `payload`; copy payloads instead of exposing mutable internal dicts. Validate finite query/stored vectors, model identity, dimensions, supported metric, IDs and payload sizes. Use a lock around registry/collection mutation and snapshot reads. Scores must satisfy SDK's higher-is-more-similar contract.

For extraction, create a private Candidate operation arena and seed only already-persisted candidates selected by the same scope and sensitivity, using `add(infer=False)` or a validated projection loader. Call actual `add(infer=True)` on bounded evidence. SDK duplicate elimination is exercised within the candidate namespace; inferred outputs never mutate Approved. This deliberately forgoes cross-status SDK dedup. Repository exact dedup and optional application review of similarity proposals handle overlap with approved records without sharing candidate context into normal recall. Do not tell the SDK that inferred output is direct user fact.

After strict extraction/result validation, commit candidates through the repository guarded transaction. If the SDK swallowed an error, returned malformed/partial results, or the operation failure flag is set, discard the whole new batch. A candidate is not durable until the repository commit succeeds. The response supplies repository IDs, never SDK IDs.

Direct, explicitly user-stated safe facts first pass deterministic classification/evidence/ownership/suppression rules and commit as active. Build their SDK projection with `infer=False`; this still embeds and may perform entity work, so the same local/cloud policy applies. Projection failure does not corrupt the authoritative record; mark semantic index unavailable and retry bounded rebuilding, rather than falsely claiming semantic readiness.

Approval updates only a current repository candidate after authenticated ownership, version/generation/evidence/TTL checks. Then project its approved version with `infer=False` into the appropriate Approved arena. Rebuild approved arenas from encrypted active records after restart; never copy an old Candidate vector row into Approved on the strength of SDK metadata. A private mapping `(arena, sdk_id) -> (repository_id, version, generation, content_digest)` is created by trusted projection code. SDK IDs and payload metadata are not ownership evidence.

Normal recall calls actual `Memory.search(query, filters=..., top_k=..., rerank=False)`; user/session identifiers are in `filters`, not top-level search parameters in this version, and its public size argument is `top_k`. Search returns score/ID proposals. Resolve mapping and re-fetch authoritative records, then independently verify user/group/course/kind/sensitivity/active status/current version/TTL/source validity/tombstone/scope generation. Return text from the repository, never SDK's `memory` or metadata. Unmapped or mismatching hits are discarded and trigger projection invalidation. Revalidate recalled references before constructing any later model prompt; deletion must not leak through a previously assembled context cache.

Existing `VectorIndex` can inform a small adapter but implementing it as the production backend would retain a departure from the requested USearch plan. Record this explicitly: preferred production target is an in-memory USearch implementation of the same adapter contract, with no `save`/`load` persistence. Exact NumPy scanning may be a reference/test backend or a separately accepted interim choice; benchmark/resolve that choice at implementation review instead of silently calling it USearch. Neither backend replaces Mem0 extraction/search orchestration.

## Repository changes required before integration

The following are actual gaps in the inspected code, not claims that they have been fixed:

1. `MemoryScope` lacks user identity and memory kind. `MemoryRecord` has one source document ID but no source version, evidence range/message, inference marker, extraction provenance or decision metadata. Add opaque backend-derived `user_id`, semantic/episodic enum, immutable evidence references, source version/content digest and inferred/direct provenance. Encrypt identifying scope/evidence and any decision text; use domain-separated keyed digests for indexed user/source/generation selectors. Preserve the documented enum/count/time leakage only. Extend uniqueness and every selector to user ownership. If existing records cannot be bound to the correct user/evidence, quarantine for migration review, never assign a generic shared user.
2. `classify_write` returns a status/reason but does not upgrade stored sensitivity when a supposedly PUBLIC string matches a sensitive pattern. After approval it could remain PUBLIC. Add effective sensitivity to classification, propagate the strongest source/content policy level, and reclassify edits. Approval cannot lower sensitivity. Strict timestamp/TTL validation must reject malformed expiration values rather than treating them as unlimited (current `is_expired` treats parse failure as no expiry).
3. `approve/_decide` reads before its update transaction, checks only candidate status, and does not version-check/increment, recheck expiry or source validity. `revise` increments version but retains old classification and does not suppress the old content. Make approve/reject/revise/delete/write compare-and-swap operations on expected record version plus scope/source generations inside a single `BEGIN IMMEDIATE` transaction. All transitions increment version. Revise writes a suppression token for the superseded content and invalidates its projections before the new version becomes available.
4. `write` checks tombstone and duplicates in separate transactions before insert. `SQLiteDatabase` locks individual transactions, not the whole read-check-write workflow. Move suppression check, evidence-liveness/generation check, dedup and insert/update into one transaction; never rely only on a Python lock for cross-process races.
5. Add durable scope/source lifecycle generations and an invalidation/deletion outbox in the same encrypted authority DB. Tombstone exact-text suppression remains keyed/encrypted as today. The primary replay barrier is a stable extraction-input identity: source/evidence IDs plus their versions/ranges/content digests and extractor-policy version, linked to every resulting candidate. Reject/correct/delete records suppression of the relevant input/evidence generation, so rerunning that batch cannot evade the user's decision by paraphrasing or changing SDK IDs. Add keyed evidence/source-revision suppression and a scope-level inference-consent generation. Where evidence association is incomplete or inference combines multiple sources ambiguously, correction/deletion conservatively pauses automatic inference from that scope's old evidence until the user explicitly re-enables a new evidence generation; deterministic direct-write paths cannot silently restore a suppressed fact. This prevents replay from old evidence without pretending exact hashes recognize arbitrary semantic equivalence. A semantically equivalent claim from entirely new evidence cannot be proven equivalent by a text hash; it remains subject to candidate review/scope consent, never automatic restoration. Explicit restore/reassert is a separate user action, not an LLM decision.
6. `cascade_delete` currently deletes records without new suppression for their sources, and course/group deletion removes tombstones. Preserve content-minimal lifecycle revocation markers for retired source/course/group generations outside the removed content rows. They contain keyed identifiers/generation/status, not deleted content. Recreated entities receive new opaque identity/generation; an old extraction cannot write into them. Source deletion revokes the source revision even if no records yet exist. Explain these minimal anti-resurrection markers in deletion policy.
7. Support multiple evidence references without silently changing first-source provenance on dedup. For the first release, conservatively invalidate a memory whenever any referenced source is deleted; later provenance-aware survivor review may be added. Add bounded snapshot/list-by-scope with generation and batch postvalidation APIs, plus outbox replay/idempotency. No durable vector/text prompt cache.
8. No explicit global-promotion contract exists in the inspected `MemoryScope`/repository: group and course are required strings, with no typed global scope, promotion record, or provenance-aware global deletion selector. Do not interpret empty strings or `'*'` as global. If promotion is required, add an explicit user-owned `scope_kind` plus destination identifier and a backend-authorized, expected-version promotion action. Promotion creates a separately approved destination record/version retaining the original evidence IDs, source/group lineage and dependency generations; it cannot convert inferred/sensitive content into directly approved public memory or broaden another user's access. A deleted source/group must invalidate dependent promoted/global memories even when their destination partition differs. The current group/course digest cascade cannot accomplish this: add reverse evidence/provenance selectors and cross-partition invalidation in the same deletion outbox. Global visibility never removes provenance deletion obligations. Until this contract is implemented, global promotion remains unavailable.

## Deletion, expiry and restart ordering

Use a short scope publication/read barrier, plus durable CAS generations. Do not hold it during model calls. Every source/document lifecycle action enters the same service boundary; calling the old repository cascade alone cannot claim full deletion.

1. Delete/correct/expire acquires the scope barrier, revokes affected operation commit tokens, and transactionally increments generations, updates/removes authority records, records minimal suppression/revocation markers and appends an invalidation outbox event. Approval checks the same current version/generation inside its transaction. Extraction carries the generation it began with; changed generation aborts commit.
2. Invalidate/evict complete affected main/entity/history arenas, all candidate/approved mappings, embedding/result/prompt-context caches and UI retained recall references. Prefer arena disposal over SDK per-memory deletion, which can re-embed entities and has best-effort cleanup. No provider/model call is needed to forget a memory.
3. The recall return path and any downstream prompt submission acquire a short read/publication barrier, postvalidate current authority, and publish only if the generation is unchanged. If deletion wins first, discard the result. If publication wins first, it is ordered before deletion; deletion then invalidates queued/UI references. Already transmitted text cannot be recalled from a remote provider and must not be described as remotely erased.
4. Confirm deletion after authority commit and local invalidation acknowledgment. If a crash occurs after commit but before acknowledgment, the record is already unrecalled by authoritative checks; startup replays the pending outbox before feature readiness. Cancellation plus generation checks stops late worker writes; destroyed arena handles cannot be reopened by cloned entity config.
5. TTL is checked on every selection and final result, not only sweep. Sweep increments affected generation and invalidates all derived states. An expired candidate cannot be approved. UTC timestamps and injected test clocks are mandatory.
6. Restart begins with empty Mem0 state. Verify master key/migrations, replay invalidations, scan owned SDK artifacts, sweep expiry, validate source/course/group liveness and only then rebuild Approved records. Candidates are loaded solely into explicit candidate operations. Tombstones/revoked evidence are never projected. Reconcile index IDs/versions against the authority and delete stray projection IDs on cache reconciliation; publish a rebuilt arena only if its generation still matches.

SQL deletion alone is not a promise of forensic erasure: encrypted historical pages/WAL/backups may retain old ciphertext under existing storage policy. Use the established checkpoint/maintenance and backup-deletion workflow, and verify absence of plaintext in DB/WAL/journal/temp/logs. Do not invent a secure-wipe guarantee for Python/SQLite or retain old plaintext versions for audit.

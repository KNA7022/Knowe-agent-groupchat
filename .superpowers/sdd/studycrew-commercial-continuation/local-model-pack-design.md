### OCR contract

The [official PP-OCRv6 documentation](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv6/PP-OCRv6.html) verifies the family exists, Small targets mobile/desktop, Small supports 50 languages, and the architecture uses PPLCNetV4 with detection and recognition modules. Recognition uses a CTC inference head; its auxiliary NRTR training head is removed for inference. Official ONNX Runtime benchmarks establish upstream support, not this application's frozen Windows behavior.

The pinned [detector configuration](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_det_onnx/blob/main/inference.yml) specifies BGR decoding, channel normalization, CHW conversion and DBPostProcess (`thresh=0.2`, `box_thresh=0.45`, `unclip_ratio=1.4`, `max_candidates=3000`). The pinned [recognizer configuration](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_rec_onnx/raw/b8f84f0b80c529de40b4fbb3544b84fa7233a513/inference.yml), successfully read as UTF-8 text, specifies BGR, `RecResizeImg` shape `[3,48,320]`, `CTCLabelDecode` and an embedded character dictionary. Its HPI examples include variable widths; they are not a verified ONNX input declaration. Preserve character order exactly. Do not take a dictionary from a different OCR generation.

Adapter contract: bounded image pixels in memory -> detection polygons/confidences -> rectified line crops -> recognized text/confidence -> page-coordinate evidence. Implement the published preprocessing/postprocessing as versioned application code, not executable YAML transforms. Expected graph interface is batched CHW image tensors with detector maps/recognizer class probabilities; **actual graph input/output names, dtypes, dynamic dimensions, opset, class count and external-data references have not been inspected**. Record them from the verified graph before activating a pack; never hardcode guessed names such as `x` or guessed output logits.

The two weight files sum to `31,039,890` bytes, about **31.04 MB decimal / 29.60 MiB**. Metadata reports detector/recognizer YAML sizes `885` and `150,579` bytes. Thus weights plus these configs total `31,191,354` bytes; this is not a final pack or installer size. Optional orientation/unwarping models, licences, runtime libraries and archive overhead are excluded. Do not advertise an unsupported “30–60 MB installed” estimate. Baseline excludes extra orientation models; test rotated/vertical input and expose unsupported/low-confidence results without claiming table or formula understanding. Validate crop geometry and decoder parity against upstream fixtures; select and licence the necessary image/geometry libraries before locking packaging.

### Embedding contracts

E5 is a 12-layer **BertModel** initialized from multilingual MiniLM, with an **XLMRobertaTokenizer**, 384-dimensional vectors and a 512-token limit; it is not an XLM-R encoder just because its tokenizer is XLM-R. Retrieval prefixes are `query: ` and `passage: ` even for Chinese. Apply attention-mask mean pooling, then L2 normalization. Sources: [official config](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/config.json), [official model card](https://huggingface.co/intfloat/multilingual-e5-small/raw/main/README.md).

Load the pinned tokenizer JSON locally with the Rust `tokenizers` binding; this avoids a runtime PyTorch/Transformers download path. The E5 JSON is `17,082,730` bytes, SHA-256 `0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39`. The listed tokenizer/config JSON trio adds `1,263` bytes. Weight + tokenizer + those configs total `135,430,817` bytes, about **135.43 MB decimal**, excluding notices and manifest. If parity requires SentencePiece fallback, its listed model adds `5,069,051` bytes; do not install both blindly. Validate normalization, special tokens, truncation, padding, masks and empty input against publisher examples; split long chunks into token-bounded passages with preserved citation locations instead of silently discarding the tail.

The official [INT8 file](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/onnx/model_qint8_avx512_vnni.onnx) exists, but its name is not proof of either hard instruction-set dependence or cross-CPU accuracy. ORT documents [U8S8 saturation considerations on AVX2/non-VNNI CPUs](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html). Release gate: inspect export configuration/graph, run CPU-only inference and retrieval quality checks on the supported baseline Windows CPUs. If unsuitable, reproducibly export/quantize **the same pinned E5 model** for generic CPU in a controlled build job, assign a distinct artifact/recipe identity and publish its verified manifest. Do not silently use FP16/O4, another E5 variant, community weights or cloud embeddings. Exact ONNX input names/types and whether this export already pools are unresolved until graph inspection; the adapter must not pool twice.

BGE-M3 supports dense 1024-dimensional embeddings and up to 8192 tokens; it needs no E5 query prefix. Initial optional pack scope is dense retrieval only; sparse and ColBERT modes are not implied. [Official model card](https://huggingface.co/BAAI/bge-m3) and [pooling config](https://huggingface.co/BAAI/bge-m3/blob/main/1_Pooling/config.json) establish CLS pooling rather than E5 mean pooling. Its ONNX listing includes `Constant_7_attr__value`, tokenizer files and the external-data blob. Listed ONNX-directory bytes sum to `2,289,765,790` (about **2.29 GB decimal**); this is the upstream directory total, not a measured final package/RAM requirement. Verify all graph external references stay inside the pinned pack, dense normalization and actual outputs before release. A later quantized BGE export would be a separate documented variant.

## Slice 1 — pack manager, without model execution

Implement proposed `backend/model_packs.py` and a small typed HTTP adapter. A bundled, reviewed catalog maps opaque `pack_id + version` to immutable publisher revision, artifact URLs, exact paths/bytes/SHA-256, licence/notice content, runtime compatibility, graph/tokenizer/preprocess identity and disk budget. Start with a bundled catalog as the trust root; SHA-256 received alongside a remote arbitrary manifest is not authenticity. Remote catalogs require a separately verified signature and rollback/revocation policy. The renderer supplies only pack/version and operation ID. No custom URL, destination path, shell command, Python module, arbitrary ONNX or executable config fields.

Proposed routes: `GET /api/capabilities/local`, `POST /api/capabilities/local/install`, `/cancel`, `/activate`, `/rollback`, `/remove`; mutations return an opaque job ID, and status polling returns bounded structured progress. Use existing local bearer/origin protections. This is a user-owned settings operation, not a fabricated Agent task/run. Agent-triggered downloads would need a separately registered governed effect and are out of this slice.

Filesystem layout under `<data_root>/model_packs`: immutable `versions/<pack-id>/<manifest-digest>/`, `staging/<opaque-job>/`, and atomically replaced active-pointer metadata. Model weights are public assets and may be plaintext; never put user sources, tokenized content, embeddings or OCR results there. Keep one previous verified version for rollback; account for all retained and staged bytes in UI.

Installation state: absent -> downloading -> verifying -> installed -> ready after runtime validation. Failure/cancellation leaves the prior active pointer intact. Stream into exclusive `.part` files with byte/time/concurrency limits; hash during download and again before activation. Commit all files as one immutable same-volume directory, then atomically replace and flush the active-pointer file. Record recovery metadata so crash after rename/before pointer update leaves a recoverable orphan, not an active partial installation. Windows sharing violations/antivirus locks produce bounded retries and a visible retryable state. Never delete the old active version before commit.

Network constraints: HTTPS only; strict peer validation; fixed catalog URLs; no cookies, provider credentials, source names or user payloads. Handle Hugging Face storage redirects only through a narrowly reviewed per-artifact CDN allowlist, bounded hops and fresh target/IP checks. Reject HTTPS downgrade, userinfo, unapproved ports, loopback/private/link-local/reserved addresses, DNS rebinding and arbitrary proxy environment configuration; validated DNS must bind to the actual connection. If that cannot be guaranteed with the selected transport, reject the route or use a controlled artifact mirror. Do not wildcard all cloud hosts. Cap actual bytes even when Content-Length is absent/false; reject unexpected encoding, partial/truncated payloads and content inconsistent with the manifest. No first-search auto-download. Offline viewing uses the bundled catalog only.

Prefer individual immutable files in v1, avoiding archives. If a future pack uses ZIP/TAR, require exact member allowlists and compressed/uncompressed byte/count/ratio ceilings. Reject absolute/UNC/drive paths, traversal after separator/Unicode normalization, NTFS alternate streams, reserved device names, trailing dot/space aliases, case-colliding or duplicate members, symlinks/hardlinks/reparse points and nested archives. Resolve every target under the managed staging root using handle/reparse-aware checks, not only string prefixes. The same containment checks apply to removal and ONNX external-data references. Pack files contain no DLL/PYD/executable or custom operator libraries; native runtime code ships in the audited app build.

Disk preflight uses manifest totals, actual allocation rounding, staged bytes, retained old version and a fixed safety reserve. Recheck during streaming; disk-full must not invalidate active packs. UI shows separate download bytes, installed bytes, previous-version bytes, temporary bytes, free space, licence/source/version, progress/cancel/retry and removal impact. “Installed” must not imply “ready”. Unknown measurements stay unknown. No claimed inference RAM figure until measured.

Removal first prevents new leases; active inference leases must finish or be cancelled before files are removed. Atomically tombstone the selected managed version, safely remove only those validated paths, retry locked files later and report pending deletion accurately. Removing a model does not remove encrypted source content or source-derived data; any derived-cache purge is separately named and scoped. Rollback rechecks the previous version against the trusted catalog and runtime compatibility; revoked/corrupt versions cannot be activated. Model switch invalidates mismatched in-memory indexes without mixing dimensions or preprocessing identities.

Focused acceptance for this slice uses small inert fixture files and an injected fake transport only: interrupted download/restart, hash mismatch, oversize/short stream, disk-full, duplicate install, cancellation, pointer corruption, crash boundaries, file locks, stale leases, traversal/reparse/case collisions, unsafe redirects/DNS and unknown pack IDs. Production catalog entries remain non-activatable until complete metadata is reviewed. No model weights are needed to prove installation transaction semantics.

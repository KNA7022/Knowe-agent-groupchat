# P2a — protected existing-record history and selected repository views

Implemented against `b9feaefd3d3bf78d7dfb18cab9da332fd714858b`, branch `feature/studycrew-foundation`. This report covers the controller-issued **P2a** brief and revised history policy, not the original full P2 acceptance. The earlier discovery found that a signed Group JSON chain alone could not prove absence of a valid-prefix rollback. The controller superseded that unnecessary lifecycle-history policy before production edits. No Group signer, transition chain, cross-file head or new commit protocol was implemented.

## Private interfaces and authority

`ProtectedLineages.completed_history(group_id, task_id, completion_path=...)` issues a backend-private `_ExistingRecordsRead` decoder only after authenticating the original P1 binding, current canonical group existence, retained same-group owner/task identity, succeeded/partial owner status and actual existing terminal Worker snapshot plus active terminal completion. Its child evidence lookup opens the existing SQLite file with `mode=ro`; missing or inconsistent evidence is an error, never a repair. IDLE alone is insufficient: the Worker snapshot must also have a terminal completion status. WAITING/BLOCKED history is not promoted by terminalizing the owner.

`ProtectedLineages.paused_history(group_id, task_id)` independently permits existing records for a PAUSED owner only under the exact original active, source/course-free scope. It checks the retained approved card, generation/digest, target, scope and expiry. Actual TaskRuntime restart recovery produces the PAUSED state in the test; neither the test nor implementation temporarily restores RUNNING or resumes a card. Completed-history scope relaxation is absent from this path.

Both modes recheck runtime closed/deletion/quarantine, Group existence, lineage authentication/revocation and owner identity/status on every repository read, including direct codec binding reads. A durable runtime deletion fence still denies after restoring old Group JSON. Cancelled/failed owners deny. Current rename, archive/restore, target removal and new source/course bindings do not revoke a completed originally source-free answer; the existing live `ProtectedAccess.guard` still denies changed scope. No original ciphertext, mapping, scope digest or AAD is rewritten.

Original provenance is established by the **existing authenticated P1 AAD version 1 plus its exact binding schema**, whose sole registration producer unconditionally rejects source/course groups and supports only optional knowledge/planning/coach targets. There is no newly invented original-scope flag. Unknown/additional/missing fields, wrong types, unsupported original role and absent Worker binding deny. Existing P1 rows are not migrated or backfilled. The reader constructor is private and issuer-gated; mode names are closed.

This slice adds **no public history DTO or endpoint**. The decoder and returned TaskEnvelope/TaskRun/CompletionEvent/TaskResult domain objects remain private, transient backend values and can contain encrypted-domain reasoning after authorized decoding. P2b must authenticate the actual user/session request for the exact group, select this manual-history interface explicitly, produce an answer/evidence-only DTO and exclude original reasoning at the final public response boundary. The current accessor owns storage/Group authorization, not HTTP/session admission. No private repository object or capability is suitable for returning to a renderer, provider, grant or background replay queue. No public reasoning projection is introduced or claimed here.

## Read-only and persistence boundaries

`storage_write` explicitly marks concrete repository mutation entry points and rejects read-only capabilities even for an idempotent or empty write attempt. Independent central checks reject codec `_binding(write=True)`, claim creation, envelope validation/sealing and Worker-run binding. Purge also rejects read-only access before revocation. The original live capability's owner/scope guards remain unchanged.

Actual tests cover envelope commit/purge; started journal, mark-started and progress; completion success/stop/transitions; outbox claim/fail/ACK; waits; decisions; resume history; reconciliation; completion-aware and delegate create/save; Worker availability mutation; codec claim/seal/binding. Each completed/paused matrix rejects 28 calls and compares authority/child SQL dumps and sampled JSON, SQLite and WAL bytes after every call. No new claims, mappings, tasks, grants or receipts appear. New read-view constructors reject missing stores/directories and skip schema creation/migration/registration; they do not turn missing history into an empty database.

The existing encrypted sinks remain TaskEnvelope files and explicit P1 SQL tables: task_runs, task_journal_v1, task_attempts_v1, completion_events_v2, task_results_v1, agent_completion_outcomes_v2, completion_outbox_v2, completion_projection_receipts_v2, wait_tokens_v2, deliveries, decision_events_v2 and task_run_history_v2. No new durable content sink or plaintext index/cache is added. SQL snapshots plus raw DB/WAL/JSON marker checks cover populated results and outboxes; the full P1 suite retains its compressed-JSON, scalar, claim, AAD and encrypted-file checks.

Byte comparisons describe the sampled application boundary with connections open. They do not claim that SQLite connection opening/closing, checkpointing, filesystem access times, shared-memory lock files, OS caches or backups never change. Already returned domain objects cannot be revoked or zeroized retroactively. Coordinated rollback of all authoritative local storage and secure physical erasure remain outside this slice's guarantee.

## Selected queries and legacy coexistence

Protected repository views use their authenticated task identity in SQL before decoding `list_active`, `active_attempts`, `worker_idle`, `pending_outbox`, `list_decisions`, `reconcile_terminal_runs`, `orphan_summary` and delegate/wrapper `list_by_state`. `pending_outbox(completion_id=...)` first authenticates the selected completion and task relation; its SQL join filters by task before outbox decode, and every returned completion relation is authenticated. Summaries authenticate selected rows rather than silently counting corrupt ciphertext as healthy history. Direct foreign keyed reads explicitly fail, including foreign legacy records and TaskEnvelope references. Corrupt selected records are not caught and skipped.

Legacy exclusion is explicit: `SQLiteCompletionStore(..., legacy_lineages=registry)` and `SQLiteTaskRunRepository(..., legacy_lineages=registry)`, propagated by `CompletionAwareTaskRunRepository`. This view has **no protected decoder capability**. The canonical registry authenticates opaque lineage IDs, including revoked cleanup rows, before SQL exclusion. Enumeration is bounded to 10,000 IDs; overflow raises instead of truncating and leaking protected records into legacy decode. Invalid registry types or corrupted mapping receipts fail closed. It does not guess authorization from model metadata or a `p1_` label. No selected capability is installed on a mutable project singleton or ambient ContextVar.

An old constructor without either selection retains P1's fail-closed behavior if it encounters protected records; it does not acquire automatic classification or decrypt authority. P2b must wire the explicit legacy view into Engine recovery. Mixed-store tests use two protected lineages in the **same group/project and physical SQLite database**, plus legacy data; each selected view sees only its intended lists/outbox/decisions/history/recovery and rejects foreign direct keys. Additional started-only, foreign-group, corrupted-row and bounded-classifier cases cover their concrete paths.

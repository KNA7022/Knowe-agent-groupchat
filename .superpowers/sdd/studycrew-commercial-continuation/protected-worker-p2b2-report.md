It requires the canonical internal workspace, registers the child through accepted `ProtectedChildren.register` before envelope/body claims, and injects per-lineage encrypted envelope, completion and run-repository dependencies. No shared mutable decrypt capability or generic storage router was added. The legacy completion view receives only the existing lineage classifier, including when that store was already open.

The real Engine scheduler (`_spawn_pending_workers` / `_process_turn`), `_run_worker`, `_new_agent`, `WorkerRuntimeFactory`, `ProviderModelAdapter`, `ProviderGatewayClient` and `WorkerRuntime` are reached. The protected branch precedes legacy profile/attachment/artifact/history processing. The holder remains the canonical gag ID. Runtime creates the actual UUID, then the selected `on_run_started` persists/binds it before MODEL_CALLED or transport send. Factory supplies no effect tools; an empty registry is now correctly distinguished from a missing registry.

The execution authority callback checks the live capability, canonical Group/owner/card and RUNNING state. It is injected into the real Gateway, which still performs its existing capability, DLP, current budget reservation/reconciliation and purpose-bound short-lived lease checks on every request. Storage access is not execution authority. A missing credential preflight produces a fixed useful BLOCKED completion with no send; authority/lease/scope/revocation changes after started are checked again before send. No credential or budget bypass was introduced.

The tests use actual temporary GroupRepository, card approvals, TaskRuntimeService/master key, child registry, SQLite, Engine/factory/Gateway/runtime, outbox projector, Hub/Store/Client and server authentication/public bridge. ## Ordering, receipts and crash policy

1. Validate current authority and canonical path; enroll child; persist encrypted envelope.
2. Create actual Worker UUID and durable started journal before model activity; invoke real Gateway.
3. While owner is still RUNNING, atomically commit encrypted completion and required outbox intents.
4. The protected branch of the real `CompletionProjector.drain` commits DELIVERY through `Hub.emit_protected`, using its returned durable `event_id`/`seq`, then stores that real receipt and ACKs local publication. Client/network ACK is not required. No JSONL/ring-presence inference is used.
5. TASK_STATE/REPORT/UI/MEMORY/KNOWLEDGE rows get honest, content-free `protected_no_derivative_copy` skip receipts. No SeenSpeech, worklog, knowledge, memory or legacy notification JSON/cache copy is made. The report-style receipt includes `review_status: pending_review`; this does not mean review happened.
6. COORDINATOR itself is retained encrypted and **pending/unclaimed**, with **no projection receipt and no ACK**. Its retained body is the durable notification intent. No `_submit_internal`, inbox/model work or automatic reconciliation is performed. Governed review remains Unit D.
7. Only after mandatory local publication/ACK does the existing TaskRuntime trusted execution finalizer/Verifier finish SUCCEEDED/PARTIAL/FAILED/CANCELLED, or pause WAITING/BLOCKED. PARTIAL is handled by the existing typed status branch; these transport fixtures directly generate success/wait/failure, not a new partial producer.

Fault tests cover before/after started, before/after completion (including notification intent), after durable event commit before its ACK, after DELIVERY ACK, after the whole drain, and before/after finalization. They use a BaseException process-interruption surrogate, close the actual stores/service and construct a new TaskRuntimeService and Engine. This is actual persistence/reopen, not an OS kill/power-loss test. Before finalization startup leaves the owner PAUSED. After committed event, accepted paused history returns the useful answer without any child SQL mutation. After finalization the true SUCCEEDED state is retained. There is no temporary RUNNING repair, late ACK, claim allocation, new Worker, provider send or coordinator inbox on actual Engine.start recovery. Reinjection/new-Worker resume is denied.

The first whole-database-equality assertion did fail in eight restart cases. Investigation isolated existing constructor initialization, not protected replay: seven explicitly named harness schema_registry `applied_at` fields refresh, `sqlite_sequence.migration_log` advances by exactly seven (existing migration-log rows do not change), and empty legacy `deliveries`/`delivery_artifacts` tables can be created. No generic migration code was changed. The final helper compares every existing table schema and every row; only those exact fields/tables are permitted. Protected journals/results/outboxes/receipts plus every other legacy row remain identical. The entire runtime database dump, including claims/catalogs, is equal across Engine.start. Pure history reads after initialization require complete child SQL dump equality without exceptions or a schema-init bypass. The restart evidence file contains actual before/after values for all nine final phases.

## Failure, lifecycle and privacy

Provider failure, malformed control, injected storage boundary failure and actual SQLite query_only write failure produce truthful FAILED; actual `stop_worker` produces CANCELLED. Their private completion access is denied by the unchanged accepted guard. The existing public TaskRuntime event/snapshot/replay supplies fixed non-sensitive status/summary and closed failure type. Client queue resync now preserves and passes this independent `task_runtime_event` channel even when an earlier unhydrated private ref denies and fences protected history. Both FAILED and CANCELLED are tested through the actual server bridge in that condition, without private fallback or error leakage.

The selected runtime never relays raw reasoning to generic Engine events. Only fixed active phases and authorized final content are published; encrypted private run state can retain necessary reasoning. Tests use distinct Chinese/ASCII instruction, answer, waiting, provider-error and reasoning markers. They scan populated files (including existing DB/WAL), gzip-decoded Store storage, decoded SQLite JSON, notification locations, Hub idempotency cache and logs. Useful authorized answers/questions are asserted, while reasoning/error markers stay absent from client frames and all private markers stay absent from persisted plaintext. Scope is the fixture's created files, not external files/backups or every possible OS artifact.

Slow transport tests exercise revoke, canonical Group delete, invalid-proof quarantine, archive, Engine shutdown and TaskRuntime close while a send is pending. A lifecycle watcher cancels pending work, and close joins/cancels tasks and closes selected client/projector/repository/SQLite handles. Revocation/deletion use the accepted durable revocation-first child cleanup. Quarantine/archive/runtime shutdown do not falsely authorize purge; started rows remain in those cases. Archive and lineage-only revoke now finish an otherwise mutable RUNNING owner through the existing trusted finalizer as FAILED/permission_denied; the resume self-review below explains this capacity correction. Quarantine/deletion and closed runtime still deny mutation, and explicit PAUSED/terminal states are unchanged. Normal shutdown does not durably revoke a retained completed lineage. Slow Client send tests archive after completion but before hydration: automatic delivery denies, explicit same-Group completed history still works. Two protected lineages plus a legacy attempt share one actual project database; revoking one preserves the other and the legacy selector.

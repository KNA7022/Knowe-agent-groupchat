## Event identity and durable commit

- Use an explicit backend-selected authenticated lineage and independently verified committed completion/outbox relation. Model event flags/metadata cannot create authority. Closed event/public DTO types only; no arbitrary tool effect, payload-based grant, raw reasoning or caller-chosen other-group store.
- Store full bounded encrypted event under the existing verified MasterKey in the selected existing completion SQLite database. Domain-separated AAD binds version/key/store, group/lineage/task/completion/outbox, immutable event ID/project/seq/type. Validate every clear field/identity separately; no weakening of global P1 opaque-ID rules. Reuse existing security primitives, but extend this typed domain explicitly rather than a generic serialization interceptor.
- Under the Hub's serialized stream sequencing, allocate sequence and commit the event, keyed semantic digest and independent identity atomically. Use appropriate per-connection SQLite FULL synchronization for this authority; state actual tested durability bounds rather than claiming hardware power-loss certification. Failure is explicit, emits/ACKs nothing. Same event identity + equivalent content returns original seq/ciphertext; conflicting authenticated content rejects. Generated timestamps/random ciphertext are not semantic idempotency keys.
- Preserve a durable content-free stream high watermark when content events are purged, so deletion/reopen cannot reuse already published sequence numbers. Counter and event commit must be atomic for this stream. Existing legacy durable watermark and protected authority restore determine the next sequence. Test cross-lineage same-project ordering, duplicate retry and deleted-highest-event reopen.
- Once authoritative commit succeeds, queue committed references in stream order before releasing the sequence gate, without waiting for network. If post-commit enqueue fails, request resync/replay; never append an old lower-seq retry as a new live event behind newer events. Network recipient ACK is not a prerequisite for task finalization. A future Worker integration must await event commit plus its other required notification intents before outbox ACK/finalization; this slice must provide a truthful typed commit result, not claim those other intents are already wired.

## Actual Hub/Store/Client paths

- Wire actual protected emit, persistent event lookup/idempotency, Store loading/replay, snapshots, startup sequence restoration and Client final hydration to the authority. JSONL alone is no longer the complete protected event source; actual replay/export entry points must use the authority, not silently omit committed output when derived references fail. Keep refs only in JSONL/gzip, ring/idempotency caches, Project pending_card, snapshots, Client live-replay buffers and queued tasks. No plaintext fallback on missing key/corruption.
- A protected record can be returned privately for transient processing, but public wire schema is a strict answer/evidence/wait/failure/fixed-phase projection. Original model reasoning is never decrypted onto the wire or placed in public nested objects. Use distinct answer/reasoning markers in tests. Fixed ephemeral phase events need no durable content reservation, but cannot sneak free-form private text into legacy emit; do not introduce streaming answer persistence without its own committed event.
- Actual successful runtime-token handshake and selected canonical group/project admission must precede protected send. Recheck current lineage/scope immediately before hydration/send. Do not trust a model/group flag or a test-added boolean as authenticated session proof. Wire a narrow existing Client/server admission hook as required; do not invent accounts/multi-tenancy. No lifecycle lock held across unbounded socket await. State fence semantics precisely: invalidation winning before hydration prevents send, plaintext already handed to socket cannot be recalled.
- Automatic reconnect/replay remains current-scope authorized. Explicit authenticated user history may use the separate completed-history capability after configuration changes; no automatic use of that relaxed reader. Source-derived/unsupported original records still deny. Restarts with PAUSED owners may read permitted existing events but never claim, ACK, repair, finalize, recreate grants or start workers/providers.
- Wire private revoke/purge to event authority, caches and queued reference invalidation; persistent deletion/quarantine fences win before content cleanup. Preserve content-free watermark/receipt only, not private bodies. Retry interrupted cleanup on the supported existing lifecycle path; no deletion of unrelated lineage/legacy records. Archive/config changes fence live delivery without erasing same-group source-free completed history ownership.
